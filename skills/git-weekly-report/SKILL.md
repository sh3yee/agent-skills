# Git 周报

根据本地 Git 历史生成简洁、可直接提交的中文周报。不得修改任何仓库内容。

## 默认请求

除非用户明确覆盖参数，否则使用以下配置：

`生成本周周报。Git 根目录是 C:\Users\she\code\vue-project，作者是 sheye，沿用我的默认模板。`

## 工作流程

1. 将“本周”定义为上海时区本周一 00:00:00 至当前时间。
2. 查找 Git 根目录下直接包含 `.git` 的子目录；在每个仓库中收集该作者在统计时间内的提交。仅当用户要求查看全部分支时才查询全部本地引用，否则使用当前分支。
3. 按完整提交哈希去重，避免同一提交因工作树或镜像仓库被重复统计。
4. 阅读提交标题和改动文件摘要，以实际改动为准归纳，不得仅根据标题推断。仅改动锁文件时，将其视为配套工作，不单独列为成果。
5. 将同项目相关提交合并为 1 至 3 条清晰的中文事项，写明具体功能、修复、接入或交付模块。已回退的改动不得作为完成成果列出。
6. 为有提交的项目创建一级标题。只有用户明确要求或模板中已有的项目，才在无提交时写 `本周暂无代码提交；`。
7. 默认仅返回完成的周报；仅在有助于说明统计范围时添加日期范围或提交数量。

## 默认项目名称

除非用户另行指定，否则使用以下显示名称：

- `BaiGuoHe` -> `白果河`
- `jiangcheng-taxi` -> `如约出行`
- `twin_cli` -> `twin_cli`

其他项目暂以目录名作为标题，直到用户提供显示名称。

## 输出格式

使用以下格式：

```text
一、项目名称
1、完成事项；
2、完成事项；

二、项目名称
1、完成事项；
```

使用客观、面向交付的中文。除非用户要求，否则不得在周报中包含提交哈希、文件路径或原始 Git 输出。
